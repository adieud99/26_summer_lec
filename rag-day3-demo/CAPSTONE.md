# Lab 3.2 캡스톤 실습 가이드

3일간 배운 것을 자기가 고른 문서로 완성한다. 배관(웹 화면·스트리밍·근거 표시·채점)은 이미 만들어져 있으니,
**RAG의 판단이 들어가는 부분**에 집중하면 된다.

## 0. 띄우기 (5분)

터미널 두 개를 쓴다.

```bash
# 터미널 1 — 백엔드
cd rag-day3-demo
./run.sh                # Windows: run.bat

# 터미널 2 — 프론트
cd rag-day3-frontend
npm install             # 처음 한 번만
npm run dev
```

http://localhost:3000 접속 → 상단 상태 표시등이 전부 초록이면 준비 완료.
빨간색이면 Ollama가 안 떠 있거나 `ollama pull bge-m3 llama3.2:3b`를 안 한 상태다.

## 1. 브론즈 (필수) — 내 문서로 동작하는 RAG 챗봇

**코드를 쓰지 않는다.** 화면에서 다음을 하면 브론즈 달성이다.

1. 왼쪽 "지식 베이스"에 자기 문서를 끌어다 놓는다 (PDF·txt·md, 여러 개 가능).
   - 강사 제공 후보: 학칙 / 오픈소스 문서 / 위키 문서 / 레시피집
   - 본인이 관심 있는 문서(게임 공략집, 장비 매뉴얼, 동아리 회칙…)를 가져오는 게 더 좋다.
2. 질문을 3개 이상 던져본다. 하나는 **문서에 답이 없는 질문**으로.
3. 답변의 `[1]` 인용 칩을 눌러 근거 청크와 유사도 점수를 확인한다.

여기까지 하면 "검색된 근거가 프롬프트에 들어가서 답이 나온다"는 흐름을 눈으로 확인한 것이다.

### 브론즈에서 꼭 해볼 실험 (설정 ⚙ 패널)

| 바꿀 값 | 무슨 일이 벌어지나 |
|---|---|
| topK 1 ↔ 8 | 근거가 부족할 때와 관련 없는 청크가 섞일 때의 답변 차이 |
| 유사도 임계값 0 → 0.7 | "문서에서 찾을 수 없습니다"가 언제부터 나오는지 |
| temperature 0 → 1.2 | 문서에 없는 말을 언제부터 섞기 시작하는지 |
| 청킹 전략/청크 크기 | 같은 문서를 다시 인덱싱해 두 사본을 만들고, 문서별 검색 대상 체크박스로 비교 |
| 시스템 프롬프트에서 인용 규칙 삭제 | 화면의 인용 칩이 사라진다 — 프롬프트가 UI 기능까지 좌우한다 |

## 2. 실버 (권장) — 검색 품질을 내 손으로 올리기

`rag-day3-demo/src/main/java/com/lecture/rag/day3/pipeline/StudentRagPipeline.java`
의 TODO 중 **하나 이상**을 구현한다. 셋 다 할 필요는 없다.

| 과제 | 메서드 | 화면에서 켜는 토글 | 어떤 문서에 효과적인가 |
|---|---|---|---|
| 질문 재작성 / multi-query | `rewriteQueries` | 질문 재작성 | 질문이 짧고 모호할 때, 대화가 이어질 때 |
| 키워드(하이브리드) 검색 | `keywordSearch` | 키워드 검색 | 모델명·조항 번호·고유명사가 많은 문서 |
| 재정렬(rerank) | `rerank` | 재정렬 | 비슷한 내용이 여러 군데 반복되는 문서 |

작업 방법:

1. 화면 우측 상단 파이프라인을 **"내 파이프라인"**으로 바꾼다.
2. 설정 ⚙에서 구현할 기능 토글을 켠다 → 아직 구현 전이라 **TODO 카드**가 뜬다
   (카드에 채워야 할 메서드 이름이 적혀 있다).
3. 메서드를 구현하고 백엔드를 재시작한다(문서는 다시 올려야 한다 — 인덱스는 메모리에만 있다).
4. 같은 질문을 다시 던진다. TODO 카드가 **실행 시간과 결과 요약이 붙은 완료 카드**로 바뀐다.
5. 설정에서 **비교 실행**을 켜면 "내 파이프라인 vs 기본 RAG"가 나란히 실행된다 —
   근거 개수·유사도·소요 시간이 정말 나아졌는지 여기서 판정한다.

> 힌트는 각 메서드의 주석에 단계별로 적혀 있다. Day2에서 만든 코드
> (`rag-day2-demo`의 `LlmReranker`, `QueryTransformDemo`)를 그대로 복사해와도 된다.

## 3. 골드 (도전) — 점수로 증명하기

두 가지 길이 있다. 하나만 해도 골드다.

**(a) 채점 붙이기** — 답변 카드의 "채점" 버튼이 Day3 오전에 배운 LLM-as-judge를 호출한다
(`eval/JudgeService.java`). 설정을 바꿔가며 같은 질문 5개를 채점해서 충실도/관련성 점수를 표로 정리한다.
"topK를 4에서 8로 올리니 충실도 평균이 3.4 → 4.2가 됐다" 같은 문장이 나오면 성공이다.

**(b) 자기 검증 구현** — `StudentRagPipeline#selfCheck`를 채운다. 생성된 답변이 근거에 실제로 있는지
LLM에게 다시 물어보고, 없으면 경고를 띄운다(Self-RAG의 축소판). 문서에 없는 질문을 일부러 던져서
경고가 뜨는지 확인한다.

## 4. 자유 확장 (원하는 사람만)

- **파이프라인을 처음부터 새로 쓰기**: `RagPipeline` 인터페이스만 구현하고 `@Component`를 붙이면
  화면 드롭다운에 자동으로 나타난다. Agentic RAG(도구 호출 루프), 질의 분해, 문서 요약 후 재검색 등
  흐름 자체가 다른 것을 만들 때.
- **새 이벤트 타입 추가**: `AgentEvent.of("myEvent").with("key", 값)` → 인스펙터 "로그" 탭에서 확인.
  디버깅 로그를 화면으로 빼는 용도로 쓰면 편하다.
- **청킹 전략 추가**: `ChunkingStrategy` enum에 상수 하나 + `split()`에 분기 추가 →
  왼쪽 패널 드롭다운에 자동 등록. Day2의 `SemanticChunker`를 옮겨보는 게 좋은 소재.
- **인덱스 영속화**: `SimpleVectorStore.save/load`로 재시작해도 문서가 남게 만들기.
- **PGVector로 교체**: Day2에서 쓰던 방식. `KnowledgeBase`의 store만 바꾸면 된다.
- **프론트 손보기**: 화면도 그대로 열려 있다. 새 지표 배지, 근거 정렬 방식, 다크/라이트 색상 등
  `rag-day3-frontend/src/components/` 를 고치면 된다.

## 자주 막히는 지점

| 증상 | 원인 / 해결 |
|---|---|
| 상단 "백엔드 응답 없음" | 백엔드가 안 떠 있음 → `./run.sh` |
| Ollama 표시등 빨강 | Ollama 미실행 (`brew services start ollama`) |
| 모델 표시등 노랑 | `ollama pull bge-m3`, `ollama pull llama3.2:3b` 안 함 |
| 답변이 "찾을 수 없습니다"만 나옴 | 유사도 임계값이 너무 높음 → 0으로 내리고 인스펙터에서 실제 점수 확인 |
| 인덱싱했는데 0자 | 스캔 이미지 PDF (텍스트 레이어 없음) → 다른 문서 사용 |
| 답변이 너무 느림 | 비교 실행/재정렬은 LLM을 여러 번 부른다. 끄고 다시 측정해볼 것 |
| 재시작하니 문서가 사라짐 | 정상 — 인덱스는 메모리에만 있다 |
| 파이프라인 토글이 "미지원" | 파이프라인을 "내 파이프라인"으로 바꿔야 한다 |
